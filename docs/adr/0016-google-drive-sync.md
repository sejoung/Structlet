# ADR 0016: Google Drive 동기화

- 상태: 채택, 실제 OAuth 환경 검증 대기
- 날짜: 2026-11-20
- 출처: Stormlet ADR 0010(같은 저작자, MIT)의 설계와 코드를 Structlet 모델에 맞게 옮김

## 배경

구성도는 브라우저와 내려받은 파일에만 있었다. 여러 기기에서 쓰거나 백업하려면 파일을 직접 옮겨야 했다. 서버 없는 정적 배포를 유지하면서 사용자의 Google Drive를 저장소로 쓴다. Stormlet에서 검증한 방식을 따른다.

## 결정

1. **선택 기능**: 공개 설정 세 개(Client ID, API 키, App ID)가 빌드에 있고, 페이지가 웹 origin(`http:`/`https:`)일 때만 켠다([설정](../google-drive.md)). `file://`로 연 HTML 한 파일에서는 끄고 파일 메뉴에 이유를 보인다. 로그인하지 않으면 Google 스크립트도 불러오지 않는다.
2. **`drive.file` 범위, 메모리 토큰**: 앱이 만들었거나 사용자가 Picker로 고른 파일만 접근한다. 토큰은 저장하지 않는다.
   - 열린 탭끼리 `BroadcastChannel`(`structlet:auth:<Client ID>`)로 남은 수명을 넘긴다. 메시지는 형식을 검증한다.
   - 만료 10분 전부터 `연장` 상태가 되고, 그동안의 클릭으로 갱신한다(`prompt: ''`). 팝업은 사용자 동작이 필요해 타이머로 열지 않는다.
3. **포트와 어댑터**: domain은 `RemoteDocuments`(열기·버전·저장·만들기·계정)와 `RemoteLinks`만 안다. 파일 형식(`.structlet`, `application/vnd.structlet+json`), 이름, HTTP 상태와 실패 사유(`auth`·`conflict`·`permission`·`full`·`missing`·`network`·`unreadable`)의 대응은 `adapters/drive`가 맡는다.
4. **세션을 감싸는 동기화**: `DriveSync`(application)가 `EditorSession`의 변경을 구독한다. 편집은 세션과 브라우저 자동 저장에 곧바로 남고, 파일에는 2초 멈춤(최대 10초) 뒤 쓴다. 다른 곳의 변경은 `EditorSession.applyExternal`로 들어와 화면과 자동 저장에는 반영되지만 실행 취소 기록에는 들어가지 않는다. 되돌리면 다른 사람의 작업을 지우게 되기 때문이다.
5. **버전 확인과 3방향 병합**(`domain/sync/merge.ts`): 저장 직전에 버전을 읽고, ETag가 있으면 `If-Match`도 보낸다. 다르면 마지막 동기화본·현재·원격을 객체·필드 단위로 병합한다.
   - 위치(x, y), 크기(width, height), 경로(routingMode, waypoints)는 각각 한 값으로 다룬다.
   - 충돌은 같은 필드를 다르게 바꾼 경우와 삭제·수정 경합뿐이다.
   - Structlet은 영역 계층이 있으므로 병합 결과를 고친다. 끝점을 잃은 연결선은 버리고, 부모 영역이 사라진 객체는 남은 가장 가까운 조상으로 옮기되 월드 위치를 지킨다. 두 쪽의 부모 변경이 합쳐져 순환이 생기면 로컬 쪽 부모를 남기고, 대상이 사라진 주석은 대상을 비운다. 결과는 항상 `validateDocument`를 통과한다.
6. **충돌은 사용자가 고른다**: 충돌 대화상자가 항목마다 "이 브라우저 / Google Drive"를 고르게 한다(모두 한쪽으로도 가능). 고르는 동안의 편집은 로컬에 남는다.
7. **연결 기억과 복구**: 연결 파일의 ID·이름·버전·계정과 마지막 동기화본을 함께 저장하거나 함께 지운다. 시작할 때 연결이 있는데 브라우저 사본이 없거나 다른 문서면 마지막 동기화본에서 시작한다. 빈 문서로 시작하면 병합이 그것을 '모두 삭제'로 읽고 Drive에 쓰기 때문이다. 같은 이유로 페이지를 숨기거나 닫을 때 브라우저 자동 저장을 즉시 한다.
8. **실패 처리**: 인증 만료는 `다시 연결`, 네트워크·요청 한도는 5·15·60초 뒤 재시도, 권한·용량·삭제·읽기 실패는 사용자가 다시 시도할 때까지 멈춘다. 다시 연결한 계정이 파일의 계정과 다르면 그 파일에 쓰지 않는다(`account`).
9. **연결 바꾸기**: 저장은 한 번에 하나만 실행한다. 다른 파일을 열거나 만들거나 연결을 끊으면 세대를 올려 이전 요청 결과를 버린다. 새로 만들기·파일 열기·샘플·Drive에서 열기 전에 밀린 편집을 먼저 저장한다. 저장할 수 없으면(다시 연결 전, 충돌 중) 바꾸지 않는다.
10. **중복 없는 생성**: 새 파일은 `files.generateIds`로 미리 받은 ID로 만든다. 응답이 유실되면 그 ID의 파일을 확인해 채택한다. 응답 전 페이지가 닫혀도 다음 연결 때 그 ID를 찾아 다시 연결한다.
11. **Drive 버튼**: 위 막대의 고정된 자리에 둔다. 상태에 따라 다음처럼 보이고, 누르면 그 상태에 맞는 동작을 한다.
    - `Drive 연결` / `Drive에 저장` / `Drive에 저장됨` / `저장 중…` / `다시 연결` / `연장` / `충돌` / `저장 안 됨`
    - 연결된 구성도에서 ⌘S는 Drive에 바로 저장한다.
    - 연결 중에 새로 만든 구성도는 첫 편집 때 기억한 폴더에 파일을 만든다.
12. **겹치는 이름**: 폴더에서 Structlet이 볼 수 있는 파일과 이름이 겹치면 `이름 (n).structlet`을 쓴다. 번호가 붙은 파일은 제목이 바뀔 때까지 번호를 유지한다.
13. **CSP**: 웹 배포 빌드에만 CSP를 넣는다. Drive가 설정된 빌드에서만 Google 로그인·Picker·Drive API origin을 연다(`scripts/csp.ts`). 인라인 스크립트와 `eval`은 계속 막는다.

## 결과

여러 기기에서 같은 구성도를 이어서 편집할 수 있고, 다른 부분을 고친 변경은 자동으로 합쳐진다. 실시간 공동 편집은 아니다.

단위 테스트는 다음을 검사한다.
- `tests/unit/domain/merge.test.ts`: 병합 규칙과 계층 복구
- `tests/unit/application/drive-sync.test.ts`: 일정·병합·충돌·재시도·일시 중지·계정·정리
- `tests/unit/adapters/drive/`: REST 계약·이름·유실 응답·실패 대응, 토큰·탭 공유·설정

`tests/e2e/drive/drive.spec.ts`는 Google 스크립트와 Drive REST를 흉내 내 다음을 확인한다: 연결, 폴더 저장, 자동 저장, ⌘S, 새로 고침 후 재연결(빈 문서를 쓰지 않음), 원격 변경 병합, 충돌 선택, 열기, 동기화 중지, 연결 해제.

같은 origin의 다른 페이지는 저장소와 토큰 채널을 공유하므로 Drive를 켜는 배포는 Structlet 전용 origin을 쓴다. 실제 계정의 동의·Picker·권한 철회·ETag는 배포 origin에서 확인해야 한다.
