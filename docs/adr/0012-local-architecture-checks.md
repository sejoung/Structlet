# ADR 0012: 로컬 구성 점검

- 상태: 채택
- 날짜: 2026-11-20

## 배경

시작 문서는 비용·보안 분석과 클라우드 계정 연동을 후속 검토로 두었다. 계정 연동과 가격 조회는 자격 증명·네트워크가 필요하므로 로컬 우선 원칙(외부 호출·API 키 없음)과 맞지 않는다. 구성도만 보고 할 수 있는 점검은 지금 넣을 수 있다.

## 결정

`adapters/analysis/checks.ts`가 문서와 서비스 카탈로그만 보고 점검한다. 결과는 아무것도 선택하지 않았을 때 속성 패널의 **점검**에 나오고, 누르면 해당 객체를 선택한다.

| 코드 | 심각도 | 조건 |
| --- | --- | --- |
| `data-in-public-subnet` | 경고 | 데이터·스토리지 역할 서비스가 이름에 public/퍼블릭/공개/dmz가 들어간 서브넷 안에 있음 |
| `client-to-data` | 경고 | 사용자·클라이언트·외부 시스템과 데이터 저장소가 직접 연결됨 |
| `unknown-service` | 정보 | 카탈로그에 없는 서비스 ID |
| `unconnected` | 정보 | 연결선이 없는 서비스 |
| `unnamed` | 정보 | 이름 없는 서비스 |
| `empty-area` | 정보 | 비어 있는 영역 |

서브넷의 공개 여부는 모델에 없어 이름으로 판단한다.

## 결과

`tests/unit/adapters/services.test.ts`가 경고 두 종과 모르는 서비스를 검사한다. 비용 추정, 보안 그룹 규칙 분석, 실제 계정과의 차이 비교는 자격 증명과 가격 데이터가 필요해 다루지 않는다.
