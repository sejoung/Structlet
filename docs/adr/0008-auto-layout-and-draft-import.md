# ADR 0008: 자동 배치와 초안 가져오기

- 상태: 채택
- 날짜: 2026-11-20

## 배경

AI 초안은 좌표 없이 검증 가능한 JSON으로 먼저 받는다. 기존 구성도를 고칠 때는 사용자가 다듬은 배치를 지키고 새 객체만 놓아야 한다. 오류 입력은 기존 문서를 바꾸면 안 된다. 선택 영역 정돈에도 같은 배치가 필요하다. Stormlet은 흐름 배치와 빈자리 배치를 썼다([참고](stormlet-reference/0019-diagram-polish.md)). 다만 포스트잇·프레임 기준이었다.

## 결정

- **배치 알고리즘(engine/layout/arrange).** `flow`(왼→오), `flow-down`(위→아래), `grid`. 흐름 배치는 형제 사이 연결선의 최장 경로로 층을 정한다. 순환을 만드는 선은 DFS 순서로 무시한다. 층 안의 순서는 이웃 위치의 무게중심으로 6번 쓸어 정하고, 교차 수가 가장 적은 순서를 남긴다. 층끼리는 가운데 정렬한다. 결과는 결정적이다.
- **자리(footprint).** 아이콘 노드는 타일과 그 아래 이름 영역을 합친 자리를, 상자 노드와 영역은 자기 크기를 차지한다. 다른 영역 안의 객체로 가는 선은 그 형제 단위로 끌어올려 센다.
- **선택 자동 배치(`layoutSelection`).** 고르지 않았거나 고정된 상자는 움직이지 않는다. 부모별로 묶어 묶음의 현재 왼쪽 위에서 배치하고, 넘치는 상위 영역은 키운다. 수동 경로는 건드리지 않는다. 이동과 영역 확장은 한 번의 undo다. 영역의 "안쪽 자동 배치"는 그 영역의 자식을 같은 방식으로 배치한다.
- **새 객체 배치(`placeNew`).** 영역을 깊은 것부터 처리한다. 한 부모 안에서 자리가 있는 형제와 선으로 이어진 새 객체는 그 옆 빈자리에, 나머지는 기존 내용 아래에 부모의 `layout`으로 놓는다. 새 영역은 내용에 맞춰 크기를 정하고, 기존 영역은 넘칠 때만 커진다.
- **초안 형식과 병합.** 형식은 [draft-format.md](../draft-format.md)에 있다. `mergeDraft`의 순서는 다음과 같다.
  1. 삭제를 적용한다.
  2. 기존 객체는 준 필드만 고친다. 고정 객체의 좌표·크기는 무시한다.
  3. 새 객체를 넣는다.
  4. 검증한다(참조·순환·종류 충돌·값).
  5. 좌표 없는 새 객체를 배치한다. 부모만 바뀐 기존 객체는 월드 위치를 지키고, 새 영역으로 옮겨진 경우만 함께 배치한다.
  6. 최종 검증 후 문서를 돌려준다. 실패하면 오류만 돌려준다.
- **한 번의 undo.** 앱은 결과 문서와 현재 문서의 차이(`diffDocuments`)를 한 패치로 실행한다.

## 결과

`tests/unit/engine/layout.test.ts`가 층 순서·순환·격자·교차 줄이기·선택 배치의 고정 유지를 검사한다. `tests/unit/adapters/draft.test.ts`는 다음을 검사한다.

- 빈 문서 초안: 겹침 없음, 부모 안에 포함
- 부분 수정: 기존 ID·위치·부모·고정 유지, 새 노드가 연결된 객체 옆에 겹치지 않게 놓임, 선 갱신, 삭제
- 오류 4종 거부, 문서화된 예시

e2e는 가져오기 후 기존 위치 유지, 한 번의 undo, 잘못된 초안 거부를 확인한다.

배치는 레이어드 휴리스틱이다. 영역을 넘나드는 선이 많은 구성은 사람이 다듬어야 할 수 있다.
