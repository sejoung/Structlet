# ADR 0013: 사용자가 불러오는 아이콘 팩

- 상태: 채택
- 날짜: 2026-11-20

## 배경

AWS 아이콘 이용 조건을 검토한 결과(제품 소유자 정리)는 다음과 같다.

- 아키텍처 다이어그램 작성과 결과물(PNG/PDF) 공유는 허용 용도다.
- 아이콘 전체를 제품에 번들링하는 것은 별도 허가가 권장된다.
- 아이콘 패키지 자체를 내려받기 상품으로 제공하려면 별도 허가가 필요하다.
- 아이콘을 수정해 자체 로고로 쓰는 것은 피해야 한다.

Google Cloud, Azure, Kubernetes도 각자 조건이 있다. 구성도의 완성도를 위해 공식 아이콘은 쓰고 싶지만, 아이콘을 배포하는 주체가 되지는 않아야 한다.

## 결정

- **Structlet은 제공자 아이콘을 포함하지 않는다.** 사용자가 제공자 공식 페이지에서 받은 zip이나 압축을 푼 폴더를 **아이콘 팩** 창에서 불러온다. 중첩 zip도 한 단계까지 읽는다(`fflate`, MIT).
- **짝짓기 규칙은 Structlet의 데이터다**(`adapters/icon-packs/matching.ts`).
  - 파일 이름을 정규화한다: 접두어 `Arch_`/`Res_`/숫자`-icon-service-`, 크기 접미사, 색 변형을 뗀다.
  - 정규화한 이름을 제공자별 별칭표와 비교하고, 없으면 카탈로그 이름과 순서 없는 단어 키로 비교한다(복수형·불용어 무시). 그룹 아이콘은 영역 종류에 짝짓는다.
  - 같은 서비스의 파일이 여럿이면 SVG, 라벨 없는 것, 48px 순으로 고른다.
  - 제공자는 고를 수도 있고, 자동이면 가장 많이 맞는 제공자로 정한다.
- **짝이 없는 아이콘**은 그 팩의 추가 서비스(`aws.pack.<이름>`)로 팔레트에 나온다.
- 이후 AWS 카탈로그에 서비스가 등록되면, 저장된 팩의 추가 서비스 ID로 등록된 이미지도 새 서비스 ID에 연결한다. 팩을 다시 불러온 뒤에도 기존 문서의 추가 서비스 ID가 같은 서비스를 가리킨다.
- **문서에는 서비스 ID만 저장한다.** 팩 데이터는 `.structlet`에 들어가지 않는다. 팩이 없는 사람이 열면 일반 기호로 보인다. 내보낸 SVG·PNG에는 쓰인 아이콘이 들어간다. 다이어그램 공유는 허용 용도다.
- **저장.** 팩은 그 브라우저의 IndexedDB(`IconPackStore`)에 둔다. IndexedDB를 못 쓰는 환경(일부 브라우저의 `file://`)에서는 메모리에만 두고 그렇다고 알린다. 팩은 켜고 끄거나 삭제할 수 있다.
- **안전.** 외부 SVG는 문서에 직접 넣지 않고 `data:` 이미지로만 그린다. 이미지로 그린 SVG는 스크립트와 외부 요청이 실행되지 않는다. 그림마다 아이콘을 `<symbol>`로 한 번만 정의하고 `<use>`로 놓는다. 화면, SVG/PNG 내보내기, 아이소메트릭 보기가 같은 방식이다.
- **한도.** 아이콘 하나 512KB, 팩 전체 60MB, 파일 12,000개, 추가 서비스 2,000개.
- **고지.** 아이콘 팩 창과 README에 제공자 상표 문구와 "제휴·보증 아님"을 적는다. Structlet 로고와 UI 장식에는 제공자 아이콘을 쓰지 않는다.

## 결과

`tests/unit/adapters/icon-packs.test.ts`는 다음을 검사한다.

- 제공자별 파일 이름 짝짓기(AWS·Azure·GCP·Kubernetes)
- 자동 감지, 48px 선택, 추가 서비스, 중첩 zip, 크기 초과 건너뛰기
- 렌더링: 화면·내보내기·아이소메트릭, 아이콘별 symbol 하나, 끈 팩 무시

e2e는 다음을 확인한다.

- AWS zip 불러오기: 캔버스·영역·팔레트·내보내기에 반영, 문서에 이미지 없음, 새로 고침 후 유지, 끄기
- Kubernetes 폴더 불러오기와 매니페스트 가져오기

상용화(유료 제공) 전에는 각 제공자의 조건을 다시 확인한다. 제공자가 파일 이름 규칙을 바꾸면 별칭표를 갱신해야 한다.
